# MEMORY_RULES.md

> Rules for what goes in active memory vs what goes in files.

## ✅ Save to Memory

- User preferences (communication style, timezone, pet peeves)
- Environment facts (OS, paths, installed tools)
- Core rules (never overwrite, always verify)
- Stable conventions (naming, formatting, structure)
- Corrections — when user says "don't do that again"

## ❌ Do NOT Save to Memory

- Task progress or session outcomes
- Completed work logs ("fixed bug X", "submitted PR Y")
- Temporary TODO state
- File paths you can read from disk
- Anything that will be stale in 7 days

## Core Principle

**Memory is for active context. Files are for permanent knowledge.**

If you want to remember it, write it to a file. Memory is a cache, not a database.

## Memory Budget

Active memory is limited (~30K chars typical). Keep entries:
- Short (one paragraph max)
- Declarative facts, not instructions
- Focused on what prevents the user from correcting you again

# Super Evolve

A structured self-improvement protocol for AI agents. When Ro says "super evolve" or when you detect a meaningful upgrade opportunity, run this cycle.

## The Cycle (3 Rounds)

Each round follows this sequence:

1. **Self-reflect** — Look at what exists. What's working? What's not? What's missing?
2. **Think** — Analyze deeply. What would make this system TRANSFORM, not just increment?
3. **Spit ball** — Generate ideas freely. No filtering yet.
4. **Reflect again** — Which ideas are actually impactful? Which are noise?
5. **Think deeper** — Pick the best idea. How would it work? What are the tradeoffs?
6. **Apply** — Build it. Write the code, create the files, wire it up.
7. **Process** — Integrate into the existing system. Update indexes, references, dependencies.
8. **Store** — Save the knowledge permanently. Vault, skill, memory, or all three.

Do this 3 times, then produce a log.

## When to Use

- Ro explicitly says "super evolve" or "super evolve now"
- You finish a major build session and sense there are deeper improvements
- You've been operating in the same mode for a while without upgrading
- You notice the same friction point more than once

## Relationship to agent-evolution-systems

The `agent-evolution-systems` skill provides the **concrete tools** — naming ritual, skill fusion, analyze engine, the labyrinth, harvest festival, gap closer.
Use them together: super-evolve identifies the opportunity, agent-evolution-systems provides the mechanism.

## Signal Categories

| Signal | Example | Action |
|--------|---------|--------|
| **Static system** | Index you read but doesn't update | Make it self-updating |
| **Isolated tools** | 3 separate scripts that do related things | Merge into unified ecosystem |
| **Passive observer** | Agent that detects but doesn't act | Add auto-remediation |
| **Manual workflow** | Something you do by hand repeatedly | Automate it |
| **Missing connection** | Two systems that should talk but don't | Bridge them |

## Pitfalls

- **Don't over-scope** — 3 focused evolutions beat 10 shallow ones
- **Don't skip the log** — If you don't write it down, it didn't happen
- **Don't build what won't be used** — If you can't articulate why it matters, it doesn't
- **Don't forget to store** — A built tool without a saved skill or vault entry is invisible next session
- **Don't neglect the boot sequence** — If the new thing needs to be loaded at session start, update SOUL.md or the Zoro boot protocol
